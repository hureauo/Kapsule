2 — Le package partagé

core/checksum.js

Une seule fonction : sha256File(filePath), qui calcule l'empreinte SHA-256 d'un fichier. Elle sert à vérifier qu'une vidéo (ou un db.sqlite) n'a pas été corrompue pendant le transfert Borne → Hub. C'est aussi la page idéale pour comprendre deux notions Node fondamentales : les streams et la construction manuelle d'une Promise.

Le fichier entier :

import { createHash } from 'node:crypto';
import { createReadStream } from 'node:fs';

export function sha256File(filePath) {
  return new Promise((resolve, reject) => {
    const hash = createHash('sha256');
    const stream = createReadStream(filePath);
    stream.on('data', chunk => hash.update(chunk));
    stream.on('end', () => resolve(hash.digest('hex')));
    stream.on('error', reject);
  });
}
JS Le préfixe node: des modules natifs

import { createHash } from 'node:crypto' : le préfixe node: désigne explicitement un module intégré à Node (la bibliothèque standard), par opposition à un paquet de node_modules. crypto (hash, chiffrement), fs (fichiers), path (chemins), os… sont tous des modules node:.

Le préfixe est optionnel historiquement ('crypto' marche aussi) mais recommandé : il lève toute ambiguïté avec un éventuel paquet installé du même nom, et c'est la convention du projet. C'est l'équivalent de la stdlib Python (import hashlib) ou des paquets standard Go (crypto/sha256).

JS Les streams Node (lecture par morceaux)

createReadStream(filePath) ouvre le fichier en flux : au lieu de charger tout le contenu en mémoire (readFileSync), il émet le fichier par morceaux (chunks). Indispensable ici : une vidéo peut faire 500 Mo — la charger entièrement saturerait la RAM.

Un stream est un émetteur d'événements : on s'abonne avec .on('événement', callback). Les trois événements utilisés :

  • 'data' — émis pour chaque chunk reçu ; on alimente le hash au fur et à mesure avec hash.update(chunk).
  • 'end' — émis quand tout le fichier est lu ; on finalise avec hash.digest('hex') (l'empreinte en hexadécimal).
  • 'error' — émis en cas de problème (fichier introuvable, lecture échouée).
LangageAnalogie
Pythonlire par blocs : while chunk := f.read(8192): h.update(chunk)
Goio.Copy(hasher, file) — le hasher est un io.Writer

Le modèle « émetteur d'événements » (EventEmitter) est partout en Node : un stream, un serveur HTTP, un processus enfant… exposent tous .on(event, cb). C'est le pendant « push » du modèle « pull » d'un itérateur. Node propose aussi une syntaxe « pull » sur les streams via for await (const chunk of stream) — Kapsule l'utilise dans le push pour relire un fichier en mémoire avant de l'envoyer. Les deux approches lisent le même stream, l'une par callbacks, l'autre par boucle asynchrone.

JS Construire une Promise « à la main »

Les streams parlent en callbacks (.on(...)), mais le reste du code veut await sha256File(path). On fait donc le pont : on enveloppe les callbacks dans une Promise construite manuellement.

new Promise((resolve, reject) => {…}) reçoit une fonction avec deux leviers :

  • resolve(valeur) — termine la Promise avec succès (ce que await renverra). Ici : resolve(hash.digest('hex')) sur 'end'.
  • reject(erreur) — termine en échec (ce que await lèvera). Ici : on passe directement reject comme handler de 'error'.

Une fois la Promise résolue/rejetée, l'appelant peut faire await sha256File(p) et récupérer la chaîne hex, ou attraper l'erreur dans un try/catch.

LangageAnalogie
Pythonun Future qu'on résout via future.set_result() / set_exception()
Goune goroutine qui envoie le résultat (ou l'erreur) dans un channel
KotlinsuspendCoroutine { cont -> cont.resume(...) }

Ce motif — « promisifier » une API à callbacks — est si courant que Node fournit util.promisify pour les callbacks au format standard (err, result) => …. Mais ici l'API est événementielle (plusieurs événements data, puis end ou error), pas un simple callback final — donc on construit la Promise nous-mêmes. Règle pratique : resolve/reject ne prennent effet qu'une fois ; les appels suivants sont ignorés. C'est pourquoi on peut passer reject à 'error' sans craindre qu'un 'data' tardif ne casse quoi que ce soit.

ℹ Le rôle du checksum dans le push

La Borne calcule le SHA-256 de chaque vidéo avant l'envoi et l'inscrit dans le manifest. À la réception, le Hub recalcule le SHA-256 du fichier reçu et le compare à celui annoncé. S'ils diffèrent → fichier corrompu en transit → le Hub répond 422 et la Borne réessaie. C'est la garantie d'intégrité bout-en-bout du transfert vidéo. Détaillé dans Flux push/pull.
