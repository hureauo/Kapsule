1 — Architecture

Flux de démarrage d'un serveur

Que se passe-t-il entre node src/index.js et le premier handler HTTP qui répond ? Le chemin est le même pour le Hub et la Borne. Suivons-le sur le Hub.

Le point d'entrée : un fichier à double usage

Le bas de apps/hub/server/src/index.js :

export function createApp(dataDir, opts = {}) {
  openRegistry(dataDir);              // 1. ouvre/crée registry.sqlite
  const app = express();             // 2. crée l'app Express
  app.use(express.json());           // 3. parse les corps JSON
  app.use('/api/auth', makeAuthRouter());          // 4. monte les routeurs
  app.use('/api/events', makeEventsRouter(dataDir));
  // … autres routeurs …
  app.use((err, req, res, next) => { /* error handler */ });  // 5. en dernier
  return app;
}

// 6. Démarrage réel — UNIQUEMENT si ce fichier est lancé directement
if (process.argv[1] === new URL(import.meta.url).pathname) {
  mkdirSync(config.dataDir, { recursive: true });
  const app = createApp(config.dataDir);
  app.listen(config.port, () => {
    console.log(`hub-server démarré sur le port ${config.port}`);
  });
}

La structure est délibérée : createApp() construit l'application sans la démarrer, et le bloc if final ne la démarre (avec .listen()) que si le fichier est exécuté directement. Pourquoi cette gymnastique ? Pour les tests.

JS Le « main module guard » : process.argv & import.meta.url

Ce if est l'équivalent ESM du fameux if __name__ == "__main__": de Python : « exécute ceci seulement si le fichier est le point d'entrée, pas s'il est importé par un autre module ».

LangageIdiome
Pythonif __name__ == "__main__":
Gofunc main() dans package main
JS (ESM)if (process.argv[1] === new URL(import.meta.url).pathname)
  • process.argv est le tableau des arguments du programme. argv[0] est le binaire node, argv[1] est le chemin du script lancé (≈ sys.argv en Python, os.Args en Go).
  • import.meta.url est l'URL du module courant (ex. file:///app/.../index.js). On la convertit en chemin de fichier avec new URL(...).pathname pour la comparer à argv[1].

Si les deux sont égaux → le fichier a été lancé par node src/index.js → on démarre le serveur. Sinon → il a été importé (par un test, qui veut juste createApp) → on ne démarre rien.

Rappel d'ESM : en modules ES, les variables CommonJS __filename / require.main n'existent pas. import.meta est l'objet standard ESM qui porte les métadonnées du module ; import.meta.url est sa seule propriété universellement disponible. D'où la conversion new URL(import.meta.url).pathname pour obtenir un chemin système comparable.

Conséquence pratique : dans les tests, on fait import { createApp } from '../src/index.js' et on obtient l'app sans qu'un serveur se mette à écouter sur un port. C'est ce qui permet à supertest d'attaquer l'app en mémoire. Le même guard est présent dans le worker et la Borne.

L'ordre des opérations dans createApp

  1. openRegistry(dataDir) — ouvre (ou crée + initialise le schéma de) registry.sqlite. C'est un singleton : le premier appel crée la connexion, les suivants la réutilisent. Voir registry.js.
  2. express() — instancie l'application Express (l'objet qui recevra les routes). Voir index.js.
  3. express.json() — un middleware global qui parse le corps JSON des requêtes entrantes et le pose dans req.body.
  4. Montage des routeurs — chaque famille d'endpoints (/api/auth, /api/events…) est branchée. L'ordre compte — c'est un point subtil d'Express détaillé dans index.js.
  5. Le gestionnaire d'erreurs — monté en dernier, avec une signature spéciale à 4 arguments. Voir index.js.

Et le worker ?

Le worker (Hub) a son propre point d'entrée src/worker/index.js avec le même guard. Au lieu de app.listen(), il lance une boucle infinie qui dépile les jobs. Les deux processus (backend HTTP et worker) tournent en parallèle, dans deux conteneurs, sur le même volume de données. Voir hub/worker.

Et la Borne ?

Identique, plus une étape : au démarrage, la Borne lance aussi le pull automatique (startAutoPull) qui interroge le Hub périodiquement. On le voit dans borne/index.js et autoPull.js.
