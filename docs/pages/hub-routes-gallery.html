hub/routes/gallery.js — Range & CSV

La galerie : c'est par ces routes que le client consulte et télécharge les vidéos d'un événement après traitement. Toutes exigent requireUser + requireOwner et un événement au statut pushed/processed. C'est la page de référence pour les requêtes Range (streaming vidéo) et la protection contre l'injection CSV.

Le streaming Range-aware

function streamFile(res, filePath, contentType) {
  const stat = statSync(filePath);
  const { size } = stat;
  const range = res.req.headers.range;

  if (range) {
    const [startStr, endStr] = range.replace(/bytes=/, '').split('-');
    const start = parseInt(startStr, 10);
    const end = endStr ? parseInt(endStr, 10) : size - 1;
    const chunkSize = end - start + 1;
    res.writeHead(206, {                              // 206 Partial Content
      'Content-Range': `bytes ${start}-${end}/${size}`,
      'Accept-Ranges': 'bytes',
      'Content-Length': chunkSize,
      'Content-Type': contentType,
    });
    createReadStream(filePath, { start, end }).pipe(res);  // ne lit QUE la tranche demandée
  } else {
    res.writeHead(200, { 'Accept-Ranges': 'bytes', 'Content-Length': size, 'Content-Type': contentType });
    createReadStream(filePath).pipe(res);
  }
}
JS Les requêtes HTTP « Range » et le code 206

Pour lire une vidéo, le navigateur n'en télécharge pas tout le contenu d'un bloc : il demande des tranches d'octets via l'en-tête Range: bytes=1000000-2000000. Le serveur répond 206 Partial Content avec l'en-tête Content-Range précisant la tranche envoyée et la taille totale. C'est ce qui permet à l'utilisateur de sauter dans la vidéo (scrubbing) sans tout charger.

Le code lit l'en-tête, calcule start/end, et ouvre le stream sur juste cette portion du fichier : createReadStream(filePath, { start, end }). Puis .pipe(res) branche ce flux de lecture sur la réponse — Node copie les octets du fichier vers le client en streaming, sans tout charger en mémoire.

NotionDétail
200Réponse complète (pas de Range demandé).
206Tranche partielle, avec Content-Range.
.pipe()Connecte un stream lisible à un stream inscriptible (≈ io.Copy en Go).

.pipe() gère automatiquement la contre-pression (backpressure) : si le client lit lentement (réseau saturé), Node ralentit la lecture du fichier pour ne pas remplir la mémoire avec des octets en attente d'envoi. C'est l'avantage des streams sur un res.send(fs.readFileSync(...)) qui chargerait toute la vidéo en RAM. Pour une borne vidéo où les fichiers font des centaines de Mo, c'est indispensable.

⛔ Invariant §11.3 : sans Range, pas de scrubbing

Si le serveur ignorait l'en-tête Range et renvoyait toujours 200 avec tout le fichier, le lecteur vidéo du navigateur ne pourrait pas se positionner à un instant T — il devrait re-télécharger depuis le début. Le support Range (206 + Content-Range) est donc obligatoire pour toute route servant une vidéo. C'est implémenté identiquement côté Borne.

L'export CSV et l'injection de formule

// Neutralise les préfixes de formule CSV (§S4/M1) : un prénom `=cmd|'/c calc'!A1`
// s'exécuterait à l'ouverture dans Excel/LibreOffice. On préfixe d'une apostrophe.
const sanitizeCsv = (v) => {
  const s = String(v ?? '');
  return /^[=+\-@\t\r]/.test(s) ? `'${s}` : s;
};
const escapeCsv = (v) => `"${sanitizeCsv(v).replace(/"/g, '""')}"`;
⛔ CSV injection (§S4/M1) : une donnée peut devenir une formule

Un invité pourrait saisir comme prénom =1+1 ou pire =cmd|'/c calc'!A1. Tel quel dans un CSV, Excel/LibreOffice interprète les cellules commençant par =, +, -, @ comme des formules — un vecteur d'exécution de commande à l'ouverture du fichier. La parade : si une valeur commence par un de ces caractères, on la préfixe d'une apostrophe ' (Excel l'interprète alors comme du texte littéral). escapeCsv ajoute par-dessus l'échappement CSV standard (guillemets doublés).

JS Arrow functions concises et String(v ?? '')

const sanitizeCsv = (v) => { … } est une fonction fléchée : une syntaxe compacte pour définir une fonction (≈ lambda Python mais avec corps possible). String(v ?? '') convertit n'importe quelle valeur en chaîne, en remplaçant null/undefined par chaîne vide d'abord — sinon String(null) donnerait "null" dans le CSV. .replace(/"/g, '""') : le drapeau g (global) remplace toutes les occurrences de guillemet par deux guillemets (échappement CSV).

La route archive : 202 « pas encore prêt »

router.get('/archive', requirePushed, (req, res, next) => {
  const archiveJob = db.prepare(`SELECT * FROM jobs WHERE event_id = ? AND type = 'archive'
                                 ORDER BY created_at DESC LIMIT 1`).get(req.params.eventId);
  const zipPath = join(dataDir, 'events', req.params.eventId, 'derived', 'archive.zip');
  if (!archiveJob || archiveJob.status !== 'done' || !existsSync(zipPath)) {
    return res.status(202).json({ pending: true });    // 202 Accepted = en cours
  }
  res.setHeader('Content-Disposition', `attachment; filename="event-${req.params.eventId}.zip"`);
  streamFile(res, zipPath, 'application/zip');
});

L'archive ZIP est produite après coup par le worker. Tant que le job archive n'est pas done (et le fichier présent), la route répond 202 (« accepté, traitement en cours ») plutôt que 404. Le front peut ainsi afficher « préparation de l'archive… » et re-tenter. Quand c'est prêt, la même route sert le ZIP via streamFile (Range-aware là aussi).

Suppression d'une vidéo : invalider l'archive

router.delete('/videos/:videoId', requirePushed, (req, res, next) => {
  // … supprime le fichier + la ligne en base (derived en cascade) …
  db.prepare(`INSERT INTO jobs (event_id, type, status) VALUES (?, 'archive', 'pending')`)
    .run(req.params.eventId);    // ré-enfile un job archive → le ZIP sera régénéré sans cette vidéo
  res.status(204).end();
});

Supprimer une vidéo rend l'archive ZIP périmée (elle contient encore l'ancienne vidéo). Plutôt que de modifier le ZIP, on ré-enfile un job archive : le worker régénérera le ZIP complet. C'est le pattern « invalider et recalculer » plutôt que « patcher en place ». La suppression en base profite du ON DELETE CASCADE du schéma (eventDbSchema) : supprimer la vidéo supprime sa ligne derived automatiquement.
