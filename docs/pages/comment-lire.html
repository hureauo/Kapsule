Le code couleur

Les blocs de code sont colorés ainsi :

// ceci est un commentaire (gris italique)
const port = 3001;                  // const/let = mot-clé (rouge), 3001 = nombre (bleu)
const message = "bonjour";          // chaîne (vert)
function maFonction(x) {            // nom de fonction (violet)
  console.log(x);                   // builtin connu (orange)
  return x * 2;
}

Souvent j'ajoute des annotations en gris directement dans les exemples pour pointer la ligne qui compte. Le code reproduit est extrait du vrai code Kapsule, parfois raccourci (signalé par // …).

Les callouts

ℹ Info

Un complément utile mais non critique.

⚠ Attention

Un point qui mérite vigilance.

⛔ Piège / invariant

Quelque chose qui casse si on l'ignore — souvent un invariant de PROJET.md §11.

Les badges de statut

Certaines fonctionnalités ne sont pas encore implémentées (suivi dans ROADMAP.md). Je les signale :

  • implémenté présent et testé dans le code
  • à venir prévu mais pas encore codé
  • vérif. humaine nécessite un vrai appareil (iPad/Raspberry) — non testable automatiquement

Organisation

La doc suit l'ordre de lecture naturel du code :

  1. Architecture — le squelette : monorepo, modules, Docker, démarrage.
  2. Package core — le code partagé entre Hub et Borne (à lire en premier, tout en dépend).
  3. Serveur Hub — le VPS : config, bases, middleware, routes, worker.
  4. Serveur Borne — le Raspberry : même structure, plus la synchronisation.
  5. Front web — le code navigateur (clients API, enregistrement vidéo).
  6. Tests — comment le projet se teste sans Docker.
  7. Transversal — flux complets, invariants, décisions, index des notions JS.
