Glossaire métier & technique

Le vocabulaire qui revient partout dans le code et la doc.

Termes métier

TermeSignification
BorneL'appareil physique sur place : Raspberry Pi (serveur) + iPad en kiosque (interface invité). Fonctionne hors-ligne. Code dans apps/borne/.
HubLe serveur central (VPS) où le client prépare l'événement et récupère les vidéos. Code dans apps/hub/.
KiosqueLe mode plein écran de l'iPad où l'invité interagit : pas de barre d'adresse, pas de sortie possible. C'est le front public de la Borne.
ÉvénementUn mariage, une soirée… L'unité de travail. Possède des questions, des sessions, des vidéos. Identifié par un UUID v4.
QuestionUne invite à laquelle l'invité répond en vidéo (« Quel est votre meilleur souvenir ? »). Configurable (durée max, compte à rebours).
SessionLe passage d'un invité : il donne son prénom + consentement, puis enregistre une ou plusieurs réponses. Identifiée par un UUID qui sert aussi de jeton d'accès (« capability token »).
Invité (guest)La personne qui enregistre. Ses données (prénom, vidéos) sont sensibles RGPD.
Consentement (consent)L'invité doit cocher explicitement consent: true avant d'enregistrer. Stocké avec horodatage.

Termes de synchronisation

TermeSignification
PullLa Borne tire depuis le Hub : récupère un événement préparé (questions, réglages) pour le rendre disponible localement. Avant l'événement.
PushLa Borne pousse vers le Hub : envoie les vidéos enregistrées et la base de l'événement. Après l'événement.
ManifestLa liste des fichiers (vidéos + base) avec leur taille et checksum, envoyée au Hub au début du push. Le Hub répond quels fichiers lui manquent → permet de reprendre un push interrompu.
HeartbeatSignal périodique que la Borne envoie au Hub pour dire « cet événement est passé live / closed ». Best-effort (échec silencieux).
BundleLe paquet renvoyé par le Hub lors d'un pull : l'événement + ses questions + ses réglages (event_meta).
Box tokenJeton secret identifiant une Borne auprès du Hub (header X-Box-Token). Stocké hashé côté Hub.

Termes techniques (stockage)

registry.sqliteLa base « annuaire » de chaque serveur. Hub : users, boxes, events, jobs, sync_log. Borne : local_events, push_state. Ne contient jamais de données invité (invariant RGPD §11.13).
db.sqlite (event store)Une base par événement, dans events/<id>/db.sqlite. Contient questions, sessions, videos, derived. C'est là que vivent les données invité.
event_metaTable clé/valeur dans le db.sqlite d'un événement (texte de consentement, timeout d'inactivité, nom…).
derivedDonnées dérivées d'une vidéo, calculées par le worker : miniature, durée, dimensions.
JobUne tâche de traitement asynchrone côté Hub (sonder une vidéo, générer une miniature, créer le ZIP). Stockée dans la table jobs, exécutée par le worker.
WorkerUn processus séparé du serveur Hub qui dépile les jobs en boucle. Voir hub/worker.
WALWrite-Ahead Logging : un mode de journalisation SQLite. Détaillé dans core/eventDbSchema.js.
ChecksumEmpreinte SHA-256 d'un fichier, pour vérifier qu'un transfert n'a pas corrompu la vidéo. Voir core/checksum.js.

Termes JavaScript / Node (survol)

Chacun a son encadré détaillé dans la page de code concernée — voir aussi l'index des notions.

NPMLe gestionnaire de paquets de Node (équivalent pip / go mod). Voir Monorepo.
WorkspaceUn sous-projet du monorepo géré par NPM. Voir Monorepo.
Module ESMUn fichier .js avec import/export. Voir ESM.
ExpressLe framework HTTP (équivalent Flask / Gin / Ktor). Voir hub/index.js.
MiddlewareUne fonction qui s'intercale dans le traitement d'une requête HTTP. Voir hub/index.js.
Promise / async / awaitLe modèle de concurrence de JS. Voir hub/routes/auth.js.
