7 — Transversal

Invariants critiques (§11)

Les 18 « pièges d'implémentation » de PROJET.md §11, avec pour chacun : ce qu'il impose, le code qui l'applique, et ce qui casserait si on l'ignorait. Ce sont les règles à ne jamais casser en modifiant le code — la plupart préviennent des bugs silencieux ou des pertes de données.

⚠ Comment utiliser cette page

Avant de modifier une route, un accès base ou un transfert de fichier, vérifie que ton changement ne viole aucun de ces invariants. Plusieurs sont contre-intuitifs (ils existent parce que le comportement naïf est faux). Les cases à cocher sont une checklist de relecture — leur état n'est pas sauvegardé, c'est un aide-mémoire visuel.

Routage & HTTP

Express matche dans l'ordre ; /:id capturerait "export". Casse : l'export CSV renverrait « ressource export introuvable ». Code : gallery.js, videos.js, questions.js.

Les <video src>, téléchargements et CSV ne peuvent pas envoyer d'en-tête Authorization. Casse : la lecture vidéo et les téléchargements échoueraient en 401. Code : hub auth, borne auth, côté front les *Url().

Le 206 + Content-Range rend le scrubbing possible. Casse : impossible de se positionner dans une vidéo (re-téléchargement depuis 0). Code : streamFile (gallery), streamFile (videos).

Safari / iOS

Safari envoie parfois un MIME générique (application/octet-stream) pour une vidéo. Casse : les uploads iPad seraient rejetés. Code : videos.js fileFilter (MIME générique + extension vidéo).

Sans, iOS force le plein écran. Casse : l'aperçu caméra et la relecture sortiraient du kiosque. Code : attachPreview (et tous les <video> du front).

fetch n'expose pas la progression d'envoi. Casse : pas de barre de progression (mauvaise UX sur Wi-Fi lent). Code : uploadVideo (XHR).

Données & base

Le libellé est copié dans videos ; supprimer une question n'orpheline pas les enregistrements (FK ON DELETE SET NULL). Casse : on perdrait le texte de la question d'une vidéo. Code : eventDbSchema.

En WAL, les dernières écritures vivent dans le -wal. Casse : on transférerait un db.sqlite incomplet → données manquantes côté Hub. Code : push.js (checkpointAndHash), nettoyage WAL/SHM à la réception sync.js.

Casse : crash entre DELETE et INSERT → session sans vidéo ; unlink avant rollback → fichier perdu alors que la base pointe dessus. Code : videos.js (transaction).

Écrire/supprimer un fichier de base ouvert = corruption. Casse : base corrompue après purge ou push. Code : closeEventDb (Hub), closeEventDb (Borne), appelé dans events DELETE, sync PUT /db, borne purge.

Tout (prénom, vidéo, session) vit dans events/<id>/. Casse : la purge (rm -rf du dossier) laisserait des données personnelles → violation RGPD. Code : schémas hub registry & borne registry.

Synchronisation

Formule min(2000·2^(n-1), 30000), 5 essais. Casse : un micro-coupure Wi-Fi ferait échouer tout le push. Code : hubClient, push (uploadFileWithRetry), XHR front.

L'état peut changer pendant l'aller-retour réseau. Casse : écraser les questions d'un événement passé live (invités en cours). Code : pull.js (étape 2).

Ne jamais faire confiance au push_state local seul. Casse : un événement marqué « poussé » alors que des vidéos manquent côté Hub. Code : sync (manifest + finalize).

Le jeton n'est stocké qu'en hash ; un 401 du Hub (token révoqué) doit être affiché clairement. Casse : push qui échoue sans explication. Code : boxAuth, push (lastError sur 401).

Matériel & déploiement (vérification humaine)

La carte SD s'use et corrompt → perte de souvenirs irremplaçables. Hors du code (déploiement Raspberry).

Caméra, HTTPS auto-signé à approuver, Range, retry : pas vérifiables sur Chrome desktop. Voir les cases 🧑 de ROADMAP.md.

Sans Internet, l'heure dérive — or consent_at est la preuve légale RGPD. Le preflight vérifie l'écart d'horloge (clock_ok), mais le matériel RTC est requis.

Performance

La vidéo est déjà compressée ; recompresser brûle du CPU pour 0 % de gain. Casse : worker lent, VPS saturé. Code : archive.js (store: true).
