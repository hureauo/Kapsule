4 — Le serveur Borne

borne/config.js

Comme côté Hub, un objet config construit depuis les variables d'environnement. La Borne a quelques réglages en plus, liés à son mode mono-utilisateur et à la synchronisation avec le Hub.

Le fichier entier :

const env = process.env;

export const config = {
  port: parseInt(env.PORT ?? '3001', 10),
  adminPassword: env.ADMIN_PASSWORD ?? 'admin123',
  techPassword: env.TECH_PASSWORD ?? 'tech123',
  jwtSecret: env.JWT_SECRET ?? 'change-me',
  dataDir: env.DATA_DIR ?? '/app/data',
  hubUrl: env.HUB_URL ?? '',
  boxToken: env.BOX_TOKEN ?? '',
  maxDataBytes: parseInt(env.MAX_DATA_BYTES || '0', 10),
  previewMode: env.PREVIEW_MODE === 'true',
  hostPort: env.HOST_PORT ?? null,
};
→ notion JS : process.env, ??, parseInt (vue dans arch-docker)

ℹ La borne d'essai (mode démo) : previewMode + maxDataBytes

docker-compose.preview.yml lance un conteneur Borne avec PREVIEW_MODE=true et MAX_DATA_BYTES=1073741824 (1 Go), sur port interne uniquement. Objectif : permettre à un client de tester la borne à distance avant l'événement réel, sans jamais envoyer les données enregistrées au Hub. Le mode démo se déduit de deux signaux : la config (previewMode, fixée par l'opérateur) ou le flag is_preview du token côté Hub (persisté dans local_events au pull, §11.20). Conséquences : push interdit (409), quota d'upload (507), reset des sessions/vidéos autorisé, et un bandeau « BORNE D'ESSAI » affiché sur le kiosque et l'admin. Voir sync.js et videos.js.

ℹ Différence clé avec le Hub : pas de table d'utilisateurs, deux mots de passe par rôle

Le Hub a une table users avec emails et comptes. La Borne, elle, n'a pas de base d'utilisateurs : juste deux mots de passe statiques qui distinguent deux rôles (§11.19). ADMIN_PASSWORD ouvre l'espace client (/admin : questions, vidéos, textes, design) ; TECH_PASSWORD ouvre l'espace technicien (/admin/tech : préflight, synchro, clôture). C'est cohérent avec l'usage : le client gère le contenu sans voir les outils de déploiement réservés à l'installateur. Pas d'inscription. La page borne/middleware/auth.js montre comment le mot de passe est comparé de façon sûre et comment le rôle est inscrit dans le JWT.

⚠ Le mode autonome (hubUrl vide)

Si HUB_URL n'est pas défini, la Borne fonctionne seule : elle sert l'événement déjà présent localement (enregistrement de vidéos, parcours invité) mais il n'y a ni pull ni push. Le démarrage saute le pull one-shot (index.js : if (config.hubUrl && config.boxToken)) et POST /sync/push-config répond 409 « mode autonome ». Utile pour une borne 100 % offline qui n'a jamais de réseau.
