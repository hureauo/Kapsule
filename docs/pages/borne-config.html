4 — Le serveur Borne

borne/config.js

Comme côté Hub, un objet config construit depuis les variables d'environnement. La Borne a quelques réglages en plus, liés à son mode mono-utilisateur et à la synchronisation avec le Hub.

Le fichier entier :

const env = process.env;

export const config = {
  port: parseInt(env.PORT ?? '3001', 10),
  adminPassword: env.ADMIN_PASSWORD ?? 'admin123',
  jwtSecret: env.JWT_SECRET ?? 'change-me',
  dataDir: env.DATA_DIR ?? '/app/data',
  hubUrl: env.HUB_URL ?? '',
  boxToken: env.BOX_TOKEN ?? '',
  pullIntervalMs: parseInt(env.PULL_INTERVAL_MS ?? '300000', 10),
};
→ notion JS : process.env, ??, parseInt (vue dans arch-docker)

ℹ Différence clé avec le Hub : un seul admin, un mot de passe

Le Hub a une table users avec emails et rôles. La Borne, elle, n'a qu'un admin local identifié par un simple mot de passe (ADMIN_PASSWORD). C'est cohérent avec son usage : un seul opérateur configure la borne sur place. Pas de base d'utilisateurs, pas d'inscription. La page borne/middleware/auth.js montre comment ce mot de passe unique est comparé de façon sûre.

⚠ Le mode autonome (hubUrl vide)

Si HUB_URL n'est pas défini, la Borne fonctionne seule : on peut créer des événements locaux directement (origine 'local'), enregistrer des vidéos, mais il n'y a ni pull ni push. C'est ce que vérifie autoPull.js (if (!config.hubUrl || !config.boxToken) return;) : sans URL ni jeton, le cycle de synchro ne fait rien. Utile pour une borne 100 % offline qui n'a jamais de réseau.
